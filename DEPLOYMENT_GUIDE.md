# ZEHNOX — Deployment Guide

This guide covers everything from previewing the site on your PC to running it on a live domain,
and how to keep updating it afterwards. No npm, no frameworks: the site is plain HTML/CSS/JS and the
admin backend is a single Node script.

---

## 1. What is in the folder

```
zehnox-site/
  content.json         every editable value (contact details, socials, team, work, insights, legal text)
  src/                 the site source (do not upload this — upload dist/)
  dist/                THE READY-TO-DEPLOY SITE. Generated by build.js. Upload this folder.
  build.js             renders src/ + content.json → dist/
  server.js            zero-dependency Node server: serves dist/, hosts the admin, stores enquiries
  admin/               the admin UI (vanilla HTML/JS)
  data/                admin credentials (hashed) + stored enquiries (never upload to a static host)
  tools/check.mjs      headless QA (developer use only)
  CONTRACT.md          how the site is built (for developers)
  README.md            short technical readme
```

Requirements: Node 18 or newer (Node 24 is installed on this PC). Nothing else.

## 2. Preview on your PC

Open PowerShell or Command Prompt:

```
cd "C:\Users\Jawad Hamza\Desktop\CCODE\zehnox-site"
node build.js
node server.js
```

- Site: http://localhost:3000
- Admin: http://localhost:3000/admin/

On the very first start the server creates the admin account: username `admin` and a random password,
printed in the console and saved in `data\initial-password.txt`. Sign in with them, then open
**Account** in the admin and set your own username and password (the initial file is deleted after that).
Sessions last 12 hours; restarting the server signs everyone out.

Stop the server with `Ctrl + C`. To use another port: `node server.js 4000`.

## 3. Fill the placeholders (do this before going live)

Everything marked with a dashed frame on the site is a placeholder from the build spec. Fill them in the admin:

| Admin section | What to fill |
|---|---|
| Site & Contact | Live domain (`https://zehnox.com`), email, phone, office address, map embed URL |
| Social | Instagram, LinkedIn, YouTube, Facebook, TikTok, X — leave blank to hide |
| Team | Founder bio and portrait; one entry per team member (name, role, discipline, bio, photo). Entries without a name show as "[Insert team member]" |
| Work | Projects to show (anonymised where required, only with client consent) |
| Insights | Articles. Each one becomes its own page at `/insights/<slug>.html` |
| Legal | Reviewed Privacy Policy, Terms of Use, Cookie Policy text |

Click **Save**. Saving rewrites `content.json` and rebuilds `dist\` automatically.
Portraits: use square or 4:5 JPG/PNG/WebP under 5 MB; the admin uploads them to `src\uploads\`.

Rules that must hold at launch (from the build spec, section 16): no invented client names, testimonials or
metrics; no public pricing; founder approval on every public page; the trading disclaimer stays where it is.

---

## 4. Build

`node build.js` (or Save / Rebuild in the admin) regenerates `dist\` from `src\` and `content.json`:
all pages, `js/content.js`, one page per insight article, `sitemap.xml`, `robots.txt`. Run it after every
content change. `dist\` is always safe to delete and regenerate.

## 5. Deploy — Option A: static hosting (recommended to start)

Upload the **contents of `dist\`** to any static host. Nothing runs on the server.
The contact form works without a backend: it prepares the enquiry in WhatsApp.

### cPanel / Hostinger / any shared hosting
1. Log in to the hosting panel, open File Manager, go to `public_html`.
2. Upload everything inside `dist\` (index.html, about.html, css/, js/, brand/, services/, solutions/, insights/ …).
   Zip `dist\` first, upload the zip, then "Extract" in the panel, then move the files so that `index.html` sits directly in `public_html`.
3. Make sure the panel's "404 page" points at `404.html` (optional but recommended).
4. Enable HTTPS (Let's Encrypt / AutoSSL in the panel).

### Netlify
1. https://app.netlify.com → "Add new site" → "Deploy manually" → drag the `dist\` folder onto the page.
2. Site settings → Domain management → add `zehnox.com` and follow the DNS instructions.
   Netlify serves `404.html` automatically.

### Cloudflare Pages
1. Dashboard → Workers & Pages → Create → Pages → "Upload assets" → upload `dist\`.
2. Custom domains → add `zehnox.com`. HTTPS is automatic.

### GitHub Pages
1. Create a repository, copy the contents of `dist\` into it, push.
2. Repository Settings → Pages → Branch `main`, folder `/ (root)`.
3. Add a file named `CNAME` containing `zehnox.com` and point the domain's DNS at GitHub Pages.

### Vercel
1. https://vercel.com/new → "Deploy without Git" is not offered in every plan; the simplest route is
   the Vercel CLI (`npx vercel dist`) or a Git repository containing only the `dist\` contents.

Updating later: edit in the local admin → Save → upload the new `dist\` again (overwrite).

## 6. Deploy — Option B: VPS with Node (admin online, enquiries stored)

Use this when you want to edit the site from anywhere and keep every enquiry in one place.
Works on any Ubuntu/Debian VPS (DigitalOcean, Hetzner, Contabo, Linode, AWS Lightsail …).

### 6.1 Server preparation
```
sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node --version      # 22.x
```

### 6.2 Upload the project
From your PC (or use FileZilla / WinSCP):
```
scp -r "C:\Users\Jawad Hamza\Desktop\CCODE\zehnox-site" user@YOUR_SERVER_IP:/var/www/
```
On the server:
```
sudo chown -R www-data:www-data /var/www/zehnox-site
cd /var/www/zehnox-site && sudo -u www-data node build.js
```

### 6.3 Run it as a service (survives reboots)
Create `/etc/systemd/system/zehnox.service`:
```
[Unit]
Description=ZEHNOX site and admin
After=network.target

[Service]
WorkingDirectory=/var/www/zehnox-site
ExecStart=/usr/bin/node server.js 3000
Restart=always
User=www-data
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```
```
sudo systemctl daemon-reload
sudo systemctl enable --now zehnox
sudo systemctl status zehnox           # should say "active (running)"
sudo cat /var/www/zehnox-site/data/initial-password.txt   # first sign-in details (change them in Account)
```

### 6.4 Domain, nginx, HTTPS
Point the domain at the server: an `A` record for `zehnox.com` and one for `www` → the server's IP.
Create `/etc/nginx/sites-available/zehnox`:
```
server {
    listen 80;
    server_name zehnox.com www.zehnox.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Optional: only allow the admin from your own IP addresses
    location /admin/ {
        # allow 203.0.113.10;
        # deny all;
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
    }
}
```
```
sudo ln -s /etc/nginx/sites-available/zehnox /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d zehnox.com -d www.zehnox.com      # HTTPS, auto-renewing
```

### 6.5 Switch the contact form to the server
Open `https://zehnox.com/admin/`, sign in, and in **Site & Contact** set:
- Contact endpoint: `/api/contact`
- Inquiry webhook (optional): a Zapier / Make / Google Sheets webhook URL to forward each enquiry

Save. From now on every submission is stored in `data/inquiries.json`, listed in the admin's
**Inquiries** tab, and the visitor still gets the WhatsApp shortcut on the thank-you screen.

### 6.6 Updating later
Edit in the online admin and click Save; the site rebuilds itself. If you change files in `src\`
on your PC, upload the changed files with scp, then click **Rebuild** in the admin or run
`sudo -u www-data node build.js` on the server. Restart only when `server.js` itself changes:
`sudo systemctl restart zehnox`.

### 6.7 Backups
Back up three things: `content.json`, `src/uploads/`, `data/`. Everything else is regenerated.

## 7. Security notes

- The admin is protected by a username and password (stored as a salted scrypt hash in `data/admin-auth.json`).
  Change them from **Account** inside the admin. Sign-in attempts are rate-limited per IP address.
- Forgot the password: stop the server, delete `data/admin-auth.json`, start it again. A fresh
  `admin` account with a new password is printed and saved in `data/initial-password.txt`.
- Always serve the admin over HTTPS (Option B) or keep the admin local only (Option A).
- Restrict `/admin/` to your IP in nginx if your connection has a fixed address.
- The server stores enquiries in a plain JSON file. Treat `data/` as personal data under your privacy policy.

## 9. Troubleshooting

| Symptom | Fix |
|---|---|
| `node server.js` says the port is in use | Run `node server.js 3001` or stop the other program |
| Lost the admin password | Stop the server, delete `data\admin-auth.json`, start again; the new first-run password is printed and saved in `data\initial-password.txt` |
| Admin says "API unreachable" | The server is not running, or you opened `admin/index.html` as a file instead of via http://localhost:3000/admin/ |
| A change does not show on the live site (Option A) | Rebuild, then upload `dist\` again; clear the browser cache |
| Fonts or animations missing | The site loads Google Fonts, GSAP and Lenis from CDNs; the visitor needs internet access to those hosts |
| Form does nothing on click | Fill every required field; the red text lists what is missing |
| Team photo not showing | Upload again through the admin (JPG/PNG/WebP, under 5 MB) and Save |
